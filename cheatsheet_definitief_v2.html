WEEK 4 DHCP & DNS
Linux DHCP (rocky1)
💡 Voorwaarden voor DHCP om te werken:
1. Rocky1 en clients zitten op hetzelfde VMnet in VMware
2. Rocky1 heeft zelf een VAST IP in hetzelfde netwerk
3. Client staat op automatisch IP ophalen
sudo dnf install dhcp-server -y
sudo nano /etc/dhcp/dhcpd.conf
💡 Inhoud dhcpd.conf (pas waardes aan naar wat gevraagd wordt!):
option domain-name "DOMEINNAAM"; ← bijv. bmc.example of bmc.test
option domain-name-servers IP-DNS-SERVER; ← IP van jouw DNS server
default-lease-time 600; ← standaard leasetijd in seconden
max-lease-time 7200; ← maximale leasetijd in seconden
subnet NETWERK netmask SUBNETMASK { ← bijv. 192.168.10.0 / 255.255.255.0
  range EERSTE-IP LAATSTE-IP; ← bijv. 192.168.10.100 192.168.10.150
  option routers GATEWAY; ← IP van de router/gateway
}
sudo systemctl enable --now dhcpd
sudo firewall-cmd --add-service=dhcp --permanent && sudo firewall-cmd --reload
Controleren of het werkt:
cat /var/lib/dhcpd/dhcpd.leases ← uitgedeelde IPs bekijken op server
ipconfig /all ← op Windows client — IP uit jouw range?
sudo dhclient ← op Linux client — IP ophalen

Linux DNS — BIND (rocky1) — vaste volgorde!
💡 Wat de vraag je geeft → wat je invult:
ZONE = domeinnaam die ze vragen bijv. zorg.local of bmc.example
SERVER_IP = IP van jouw Linux server
NETWERK = het netwerk bijv. 192.168.20.0/24
HOSTNAME = naam van de server bijv. rocky1
Stap 1 — Installeren:
sudo dnf install bind bind-utils -y
Stap 2 — named.conf aanpassen:
sudo nano /etc/named.conf
→ Aanpassen (pas SERVER_IP, NETWERK en ZONE aan!):
listen-on port 53 { 127.0.0.1; SERVER_IP; };

← SERVER_IP = vast IP van rocky1 (geen /24 nodig — dit is één specifiek IP)

allow-query { localhost; NETWERK/24; };

← NETWERK/24 = heel netwerk bijv. 192.168.15.0/24 (wél /24 nodig — dit is een heel netwerk)

zone "ZONE" IN {
  type master;
  file "ZONE.zone";
};
Stap 3 — Zone bestand aanmaken:
sudo nano /var/named/ZONE.zone
→ Inhoud (CAPSLOCK = jij aanpassen, kleine letters = altijd hetzelfde laten!):
$TTL 300
@ IN SOA HOSTNAME.ZONE. hostmaster.ZONE. (
  2026010601 3M 1M 30D 1M )
@ IN NS HOSTNAME.ZONE.
HOSTNAME IN A SERVER_IP

Voorbeeld voor school.local met srv1 op 10.0.0.1:
@ IN SOA srv1.school.local. hostmaster.school.local. (
  2026010601 3M 1M 30D 1M )
@ IN NS srv1.school.local.
srv1 IN A 10.0.0.1

Wat je aanpast: HOSTNAME, ZONE, SERVER_IP
Wat je NOOIT aanpast: hostmaster, $TTL, 3M 1M 30D 1M, IN SOA, IN NS, IN A
Stap 4 — Rechten instellen:
sudo chown named:named /var/named/ZONE.zone
Stap 5 — Starten & firewall:
sudo systemctl enable --now named
sudo firewall-cmd --add-service=dns --permanent && sudo firewall-cmd --reload
Stap 6 — Testen:
dig +noall +answer HOSTNAME.ZONE @127.0.0.1
→ Zie je het IP verschijnen? Dan werkt DNS!

WEEK 5 Linux Storage — Partities, LVM & RAID
Schijven bekijken — welke is leeg?
lsblk ← overzicht alle schijven
💡 Hoe zie je welke schijf leeg is?

NIET leeg → heeft partities eronder:
nvme0n1 20G disk
├─nvme0n1p1 1G part /boot
└─nvme0n1p2 19G part

WEL leeg → niets eronder:
nvme0n3 20G disk

→ Gebruik altijd de schijf zonder streepjes eronder!
→ Schijf waar Linux op staat (met /boot) NOOIT aanraken!
sudo fdisk -l ← gedetailleerd overzicht
Partitie aanmaken + mounten — altijd deze volgorde!
Stap 1 — Partitie aanmaken:
sudo fdisk /dev/nvme0n2
→ In fdisk: n → p → 1 → Enter → Enter → w
Stap 2 — Bestandssysteem aanmaken:
sudo mkfs.ext3 /dev/nvme0n2p1
→ Zonder dit kun je de partitie niet gebruiken!
Stap 3 — Map aanmaken:
sudo mkdir /data/map
→ De map waar je de partitie aan koppelt
Stap 4 — Mounten (koppelen):
sudo mount /dev/nvme0n2p1 /data/map
→ Nu kun je de partitie gebruiken
Stap 5 — Controleren:
df -h ← zie je de partitie in de lijst?
Stap 6 — Automatisch mounten bij herstart (fstab):
sudo nano /etc/fstab
→ Voeg onderaan toe (pas aan naar jouw schijf/map!):
/dev/nvme0n2p1 /data/map ext3 defaults 0 0
sudo systemctl daemon-reload
sudo mount -a ← testen zonder herstart
LVM aanmaken — vaste volgorde!
💡 Wat de vraag je geeft → wat je invult:
SCHIJF = lege schijf uit lsblk (bijv. nvme0n2)
PARTITIE = schijf + p1 (bijv. nvme0n2p1)
VG_NAAM = naam van de volume group die ze vragen
LV_NAAM = naam van het logical volume die ze vragen
GROOTTE = grootte die ze vragen (bijv. 100M of 2G)
MAPNAAM = map waar je hem op mount
Stap 1 — Kijk welke schijf leeg is:
lsblk
→ Schijf zonder mountpoint = mag je gebruiken
nvme0n2p1 20G part ← geen mountpoint = veilig
nvme0n1p1 1G part /boot ← heeft mountpoint = NOOIT aanraken!
Stap 2 — Partitie aanmaken:
sudo fdisk /dev/SCHIJF
→ n → p → 1 → Enter → Enter → w
Stap 3 — Oud bestandssysteem wissen (alleen als er al iets op stond!):
sudo wipefs -a /dev/PARTITIE
→ Alleen doen als pvcreate een fout geeft over een "signature"
→ Controleer eerst met lsblk dat er geen mountpoint op staat!
Stap 4 — Physical Volume:
sudo pvcreate /dev/PARTITIE
Stap 5 — Volume Group:
sudo vgcreate VG_NAAM /dev/PARTITIE
Stap 6 — Logical Volume:
sudo lvcreate -n LV_NAAM -L GROOTTE VG_NAAM
sudo lvdisplay ← controleer of aangemaakt
Stap 7 — Bestandssysteem aanmaken:
sudo mkfs.xfs /dev/VG_NAAM/LV_NAAM
Stap 8 — Mounten:
sudo mkdir /data/MAPNAAM
sudo mount /dev/VG_NAAM/LV_NAAM /data/MAPNAAM
df -h ← zie je hem in de lijst?
Stap 9 — Automatisch mounten (fstab):
sudo nano /etc/fstab
→ Voeg toe:
/dev/VG_NAAM/LV_NAAM /data/MAPNAAM xfs defaults 0 0
sudo systemctl daemon-reload && sudo mount -a
RAID1 aanmaken
💡 RAID1 = twee schijven spiegelen. Je hebt 2 lege schijven nodig!
Stap 1 — Partities aanmaken op beide schijven:
sudo fdisk /dev/nvme0n3 ← n, p, 1, Enter, Enter, t, fd, w
sudo fdisk /dev/nvme0n4 ← zelfde stappen
Stap 2 — RAID array aanmaken:
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/nvme0n3p1 /dev/nvme0n4p1
cat /proc/mdstat ← voortgang bekijken
💡 [2/2] [UU] = beide schijven actief ✅
Wacht tot de resync regel verdwenen is!
Stap 3 — Bestandssysteem aanmaken op de RAID array:
sudo mkfs.ext3 /dev/md0
→ /dev/md0 is de RAID array — niet de losse schijven!
Stap 4 — Map aanmaken en mounten:
sudo mkdir /data/MAPNAAM
sudo mount /dev/md0 /data/MAPNAAM
df -h ← controleer of gemount
Stap 5 — Automatisch mounten (fstab):
sudo nano /etc/fstab
→ Voeg toe:
/dev/md0 /data/MAPNAAM ext3 defaults 0 0
sudo systemctl daemon-reload && sudo mount -a
WEEK 6 Systeembeveiliging — Rechten, SSH & SELinux
Windows — AGDLP principe
💡 Account → Global group → Domain Local group → Permission
Gebruiker in globale groep → groep krijgt rechten op map
  1. Maak Global group aan: bijv. G_Huisartsen
  2. Maak Domain Local group aan: bijv. DL_Recepten_Volledig
  3. Voeg G_Huisartsen toe als lid van DL_Recepten_Volledig
  4. Geef DL_Recepten_Volledig rechten op de map
Share aanmaken op Core:
New-SmbShare -Name "naam" -Path "C:\map" -FullAccess "BMC\DL_Volledig" -ReadAccess "BMC\DL_Lezen"
net share ← alle shares bekijken
⚠️ Firewall openen op Core:
netsh advfirewall firewall set rule group="File and Printer Sharing" new enable=Yes
Linux — Gebruiker & Groep aanmaken
sudo groupadd groepsnaam
sudo useradd -m gebruikersnaam
sudo usermod -aG groepsnaam gebruikersnaam
⚠️ Hoofdletter G! -aG niet -ag
id gebruikersnaam ← controleer of groep erin staat
su - gebruikersnaam ← inloggen als andere gebruiker
Linux — Bestandsrechten
💡 Altijd deze 3 stappen in deze volgorde!
Stap 1 — Map aanmaken:
sudo mkdir /data/mapnaam
→ Maakt de map aan. Nog geen rechten, nog geen groep.
Stap 2 — Eigenaar en groep instellen:
sudo chown root:groepsnaam /data/mapnaam
→ root = eigenaar van de map, groepsnaam = welke groep bij de map hoort.
Stap 3 — Rechten instellen:
sudo chmod 770 /data/mapnaam
→ Bepaalt wat owner en group mogen doen.
770 = owner+group mogen alles, others niets
755 = iedereen mag lezen, alleen owner schrijven
700 = alleen owner, niemand anders

7 = rwx (alles) | 5 = r-x (lezen) | 0 = niets
Volgorde cijfers: owner | group | others
Controleren:
ls -l /data ← rechten bekijken
Speciale bits
SUID — uitvoeren met rechten van eigenaar:
sudo chmod u+s /bestand
find / -user root -perm -4000 2>/dev/null ← SUID bestanden zoeken
SGID — nieuwe bestanden krijgen groep van map:
sudo chmod g+s /map
Sticky bit — alleen eigenaar mag verwijderen:
sudo chmod +t /map
Symbolic link:
sudo ln -s /origineel /link
SSH beveiliging
sudo systemctl status sshd ← SSH aan of uit?
ssh gebruiker@IP ← verbinding maken
Root login uitzetten:
sudo nano /etc/ssh/sshd_config
→ Zoek de regel PermitRootLogin en verander naar:
PermitRootLogin no

no = uitzetten (root mag niet meer inloggen via SSH)
yes = aanzetten (root mag inloggen)
sudo systemctl restart sshd ← altijd herstarten na aanpassing!
SELinux
💡 SELinux blokkeert Apache als de map het verkeerde label heeft.
Altijd: semanage EERST, dan restorecon
ls -Z /map ← labels bekijken
sudo grep http /var/log/audit/audit.log | audit2why ← fout analyseren
Permanent oplossen:
sudo semanage fcontext -a -t httpd_sys_content_t "/pad(/.*)?"
sudo restorecon -R -v /pad

VyOS VyOS Router configureren
Basis — Hoe werkt VyOS?
💡 VyOS is een Linux router. Je typt commando's in de terminal. Er zijn twee modi:
- Normale modus → alleen bekijken
- Configuratie modus → instellingen wijzigen (na "configure")
configure ← ga naar configuratie modus (prompt wordt #)
commit ← activeer de wijzigingen
save ← sla op zodat het na herstart nog werkt
exit ← verlaat configuratie modus
show interfaces ← bekijk alle interfaces en IPs
show ip route ← bekijk de routingtabel
IP adressen instellen op interfaces
💡 Elke interface krijgt een IP in het netwerk waar hij op zit. Verander de IPs naar wat de opdracht vraagt!
configure
set interfaces ethernet eth0 address 172.16.3.252/24 ← eth0 = Leased netwerk (verbinding met RRAS1)
set interfaces ethernet eth1 address 192.168.5.252/24 ← eth1 = Amersfoort netwerk (intern LAN)
set interfaces ethernet eth2 address 10.13.14.252/24 ← eth2 = DMZ2 netwerk
set interfaces ethernet eth3 address dhcp ← eth3 = NAT/internet (krijgt automatisch IP)
commit && save
⚠️ Welke eth bij welk netwerk hoort → controleer MAC adressen in VMware Settings!
RIP Routing instellen
💡 RIP zorgt dat VyOS automatisch routes uitwisselt met RRAS1. Je geeft op welke netwerken VyOS kent. Verander de netwerken naar wat de opdracht vraagt!
configure
set protocols rip network 172.16.3.0/24 ← Leased netwerk (richting RRAS1)
set protocols rip network 192.168.5.0/24 ← Amersfoort netwerk
set protocols rip network 10.13.14.0/24 ← DMZ2 netwerk
commit && save
💡 Internet interface (eth3/NAT) NIET toevoegen aan RIP!
NAT instellen (internet voor interne netwerken)
💡 NAT zorgt dat computers in het interne netwerk via VyOS internet kunnen gebruiken. Elke intern netwerk krijgt een eigen regel. Verander eth3 naar je internet interface en de netwerken naar wat de opdracht vraagt!
configure
set nat source rule 100 outbound-interface eth3 ← eth3 = internet kant
set nat source rule 100 source address '192.168.5.0/24' ← intern netwerk
set nat source rule 100 translation address masquerade ← vertaal naar extern IP
set nat source rule 200 outbound-interface eth3
set nat source rule 200 source address '10.13.14.0/24'
set nat source rule 200 translation address masquerade
commit && save
Default route instellen (internet)
💡 Dit zegt: "al het verkeer dat nergens anders naartoe kan, stuur naar het internet". De gateway is het IP van VMware NAT (192.168.220.2 of vergelijkbaar)
set protocols static route 0.0.0.0/0 next-hop 192.168.220.2 distance 1
commit && save

Linux DNS Server (BIND) op Rocky1
💡 BIND is de meest gebruikte DNS server op Linux
Stap 1 — Installeren:
sudo dnf install bind bind-utils -y
Stap 2 — Configureren (named.conf):
sudo nano /etc/named.conf
💡 Aanpassen in named.conf:
listen-on port 53 { 127.0.0.1; 192.168.15.1; };
allow-query { localhost; 192.168.15.0/24; };

zone "bmc.example" IN {
    type master;
    file "bmc.example.zone";
};
Stap 3 — Zone bestand aanmaken:
sudo nano /var/named/bmc.example.zone
💡 Inhoud zone bestand:
$TTL 300
@ IN SOA rocky1.bmc.example. hostmaster.bmc.example. (
    2026010601 ; serienummer
    3M ; refresh
    1M ; retry
    30D ; expire
    1M ) ; minimum

@ IN NS rocky1.bmc.example.
rocky1 IN A 192.168.15.1
Stap 4 — Rechten instellen:
sudo chown named:named /var/named/bmc.example.zone
Stap 5 — Configuratie controleren:
sudo -u named named-checkconf -z
💡 Alleen "loaded serial" meldingen = goed. Errors = fout in configuratie
Stap 6 — Starten:
sudo systemctl enable named
sudo systemctl start named
sudo systemctl status named
Stap 7 — Firewall openzetten:
sudo firewall-cmd --add-service=dns ; sudo firewall-cmd --runtime-to-permanent
Stap 8 — Testen:
dig +noall +answer rocky1.bmc.example @127.0.0.1
dig +noall +answer rocky1.bmc.example @192.168.15.1
DHCP DHCP Server — Linux (Rocky) & Windows (Core)
Linux DHCP Server op Rocky1
💡 Rocky1 deelt automatisch IPs uit aan clients op hetzelfde netwerk
Stap 1 — Installeren:
sudo dnf install dhcp-server -y
Stap 2 — Configureren:
sudo nano /etc/dhcp/dhcpd.conf
💡 Inhoud van dhcpd.conf — verander de IPs naar wat de opdracht vraagt!

option domain-name "bmc.example";
option domain-name-servers 192.168.15.1;

default-lease-time 600;
max-lease-time 7200;

subnet 192.168.15.0 netmask 255.255.255.0 {
    range 192.168.15.100 192.168.15.150;
    option routers 192.168.15.254;
}
Stap 3 — Starten:
sudo systemctl enable dhcpd
sudo systemctl start dhcpd
sudo systemctl status dhcpd ← controleer of hij draait
Stap 4 — Firewall openzetten:
sudo firewall-cmd --add-service=dhcp --permanent
sudo firewall-cmd --reload
Stap 5 — Leases bekijken:
cat /var/lib/dhcpd/dhcpd.leases ← welke IPs zijn uitgedeeld?
Windows DHCP Server op Core1
💡 Core server heeft geen GUI — alles via PowerShell
Stap 1 — Installeren:

Stap 2 — Scope aanmaken:
💡 Verander de IPs naar wat de opdracht vraagt!

Set-DhcpServerv4Scope -ScopeId 192.168.14.0 -State Active

Start-Service DHCPServer
